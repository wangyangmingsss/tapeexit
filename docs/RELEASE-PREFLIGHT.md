# Formal release evidence

Production signing stays disabled. These commands collect and check evidence for
a reviewed release proposal; they never grant approval or modify config.ts.

## Actual gateway verification

Copy release-profile.example.json into an ignored release-artifacts directory.
Fill the actual clean source commit, release manifest SHA-256, container,
canonical TapeOut name (for example `1.2.344.tape`), and two public HTTPS origins.
The site host label must match the TapeOut name, for example `1-2-344`.
Operator names must differ. Their organizational independence needs human review.
Gateway verification reads only the identity and gateways fields; asset and
evidence fields may remain unfilled while collecting evidence.

Run `npm run verify:gateways -- release-artifacts/release-profile.json` after
installing Chromium with Playwright. Each gateway gets a fresh browser context.
The tool waits for the actual client controller and TapeExit entry, checks every
release file's full bytes, MIME type and client identity headers, and checks the
reserved status route. The backup context blocks the primary origin and first
proves that a request to it fails, before loading the backup. Failed runs remove
the old success report.

This is an actual-origin test, not a fixture result. It checks observable client
behavior, not the authenticity of an arbitrary gateway's worker code. Compare
the deployed gateway with the pinned TapeKit build and review TLS/DNS/hosting.
The command does not request wallet access or transactions.

## Evidence preflight

Run actual container readback with `verify:publication`. Its report includes the
source commit, manifest digest, observed time and container live state.
Populate the profile's reviewed assets with address, runtime code hash, decimals
and review-document SHA-256. Candidate metadata is insufficient.

Supply five JSON reports, each bound to `sourceCommit`, `manifestSha256`,
`chainId:196`, `container` and ISO `observedAt`. All must be at most 24 hours old
when checked. An older independent review may be retained as an attachment to a
fresh reviewer confirmation for the identical release. Required declarations:

| Report | Required fields |
| --- | --- |
| publication | `status:published-bytes-checked`, `containerLive:true` |
| assets | `status:REVIEWED`, `assets` exactly matching the normalized profile |
| wallet | `status:REAL_ORIGIN_ACCEPTED`, `synthetic:false`, one configured `origin`, `chainObserved:196` |
| gateways | Generated by `verify:gateways`; two origins, exact bytes and primary-blocked recovery |
| security | `status:REVIEW_COMPLETED`, named `reviewer`, `unresolvedCritical:0`, `unresolvedHigh:0` |

Wallet connectivity exports from the local harness are deliberately insufficient.
Actual-wallet evidence must document the wallet/version, permissioned task,
origin, network and observed outcome. Do not edit a synthetic result to claim
acceptance. Review reports are authored by actual reviewers, not generated by
the preflight command.

Hash each report's exact bytes into the matching `evidence` reference. References
must be project-relative JSON files, with no traversal or escaping symlinks.
Run `npm run preflight:release -- release-artifacts/release-profile.json`.
It rejects stale, mixed, tampered or incomplete evidence and a dirty/different
source release. Successful output is
`EVIDENCE_CONSISTENT_REQUIRES_HUMAN_APPROVAL`, with `signingApproved:false`.

Declarations and hashes do not authenticate a reviewer's independence or prove
that a supplied human report is truthful. Human acceptance, token behavior and
governance review, publication budget approval, and a separately reviewed source
change are still required before any production signing release. This tool is
compatible with the current unsigned candidate format; an approved release
format needs its own reviewed changes to the manifest/publication guard.
