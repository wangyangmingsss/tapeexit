# Formal release evidence

Production signing stays disabled. These commands collect and check evidence for
a reviewed release proposal; they never grant approval or modify config.ts.

## Actual gateway verification

Copy release-profile.example.json into an ignored release-artifacts directory.
Fill the actual clean source commit, release manifest SHA-256, container,
canonical TapeOut name (for example `1.2.344.tape`), and two public HTTPS origins.
The site host label must match the TapeOut name, for example `1-2-344`.
Operator names must differ. Their organizational independence needs human review.
Gateway verification reads only the identity and gateways fields; asset and
evidence fields may remain unfilled while collecting evidence.

Run `npm run verify:gateways -- release-artifacts/release-profile.json` after
installing Chromium with Playwright. Each gateway gets a fresh browser context.
The tool waits for the actual client controller and TapeExit entry, checks every
release file's full bytes, MIME type and client identity headers, and checks the
reserved status route. The backup context uses a loopback CONNECT proxy that
refuses primary-host HTTPS tunnels, including requests from Service Workers.
It first proves that a primary connection was blocked before loading the backup.
The proxy passes other HTTPS tunnels without decrypting TLS, rejects other
ports and credentials, and closes sockets at shutdown. Failed runs remove the
old success report. Ordinary page routing is insufficient for SW-originated traffic.

This is an actual-origin test, not a fixture result. It checks observable client
behavior, not the authenticity of an arbitrary gateway's worker code. Compare
the deployed gateway with the pinned TapeKit build and review TLS/DNS/hosting.
The command does not request wallet access or transactions.

## Evidence preflight

Run actual container readback with `verify:publication`. Its report includes the
source commit, manifest digest, observed time and container live state.
Populate the profile's reviewed assets with address, runtime code hash, decimals
and review-document SHA-256. Candidate metadata is insufficient.

Supply five JSON reports, each bound to `sourceCommit`, `manifestSha256`,
`chainId:196`, `container` and ISO `observedAt`. All must be at most 24 hours old
when checked. An older independent review may be retained as an attachment to a
fresh reviewer confirmation for the identical release. Required declarations:

| Report | Required fields |
| --- | --- |
| publication | `status:published-bytes-checked`, `containerLive:true` |
| assets | `status:REVIEWED`, `assets` exactly matching the normalized profile |
| wallet | `status:REAL_ORIGIN_ACCEPTED`, `synthetic:false`, one configured `origin`, `chainObserved:196`, `exit:{account,tokenId,transactionHash}` for the actual direct exit |
| gateways | Generated by `verify:gateways`; two origins, exact bytes and primary-blocked recovery |
| security | `status:REVIEW_COMPLETED`, named `reviewer`, `unresolvedCritical:0`, `unresolvedHigh:0`, `attestation` references to original signed artifacts |

Wallet connectivity exports from the local harness are deliberately insufficient.
Actual-wallet evidence must document the wallet/version, permissioned task,
origin, network and observed outcome. Do not edit a synthetic result to claim
acceptance. Review reports are authored by actual reviewers, not generated by
the preflight command.

Hash each report's exact bytes into the matching `evidence` reference. References
must be project-relative JSON files, with no traversal or escaping symlinks.
Run `npm run preflight:release -- release-artifacts/release-profile.json TRUSTED_REVIEWER_PUBLIC_KEY_SHA256`.
It rejects stale, mixed, tampered or incomplete evidence and a dirty/different
source release. Successful output is
`EVIDENCE_CONSISTENT_REQUIRES_HUMAN_APPROVAL`, with `signingApproved:false`.

### Original Signed Review

Use `prepare:review` to freeze the exact clean source, lockfile and candidate files. The actual reviewer
completes and signs their report as described in `SECURITY-REVIEW-PACKET.md`. The security summary's
`attestation` object has four `{path,sha256}` references: `packet` and `report` are `.json`,
`signature` is a detached binary `.sig`, and `publicKey` is a `.pem` file.
See `security-review.example.json` for an intentionally incomplete template.

The CLI requires the SHA-256 of the public-key file as a separate argument. Confirm this value with
the actual reviewer through a trusted channel; do not simply copy it from an untrusted summary.
Preflight reloads the original packet, signed report, signature and public key through bounded
project-contained file reads. It independently verifies the signature, exact current Git archive
and dependency lock, manifest, eight review surfaces, exclusions and findings. The summary reviewer
and unresolved counts must match the signed statement. A prior `verify:review` result, a status-only
JSON document, or updated file hashes without a valid new signature cannot substitute for these inputs.
No private key is read by preflight.

### Fresh Chain Recovery

The actual wallet report includes the expected account, canonical decimal NFT ID and nonzero transaction
hash under `exit`. See `real-wallet-acceptance.example.json`; placeholders cannot pass.
After authenticating the signed review, the CLI reads that transaction through `StrictRpc` and reruns
`inspectRecoveryOutcome`. It does not import a saved recovery pass. The result must be finalized,
have checked collection/transfer events and matching block-end balances/liquidity, and match the
declared account, NFT and hash. Pending, reverted, reorged, mismatched or unavailable historical state
prevents success. A historical publication transaction fails the manager/calldata checks.
Both actual recovered token addresses and precisions must occur in the reviewed release asset policy.
This does not independently establish token source correspondence or future proxy/issuer governance.

The output retains the authenticated review statement and fresh chain observations. Source/build identity
is checked again after RPC reads. Failed attempts remove the prior preflight result. The command does
not request the wallet, sign, broadcast, clear pending locks, alter assets or change production gates.

A chain transaction cannot prove which origin or extension created it. Raw browser/wallet observations,
actual-origin acceptance and fault-task evidence remain necessary for human review. Block-end balances
cannot isolate every other operation in the same block. No report is claimed while actual inputs are absent.

Signatures and hashes do not authenticate a reviewer's independence or prove
that a supplied human report is truthful. Human acceptance, token behavior and
governance review, publication budget approval, and a separately reviewed source
change are still required before any production signing release. This tool is
compatible with the current unsigned candidate format; an approved release
format needs its own reviewed changes to the manifest/publication guard.
