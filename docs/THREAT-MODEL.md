# TapeExit 威胁模型

## 信任与范围

保护目标是减少原站失联时的前端和私有 API 依赖。应用不修复协议漏洞，不绕过质押、时间锁和资产冻结，也不能恢复丢失的密钥。

签名者、原 V3 合约、资产合约、X Layer 排序与最终性、浏览器和钱包均保留信任。两个 RPC 的运营方身份是发布配置中的人工归属判断，不是独立性密码学证明；两方串通或共同上游故障仍可误导应用。

TapeOut 的文件校验不消除网关启动文件、浏览器、DNS/TLS 与 Service Worker 更新的信任。可修改容器不是不可变发行；必须另存可信的 manifest 摘要。激活到期、代理实现变化、分块缺失可能令站点不可读。

## 已实施边界

| 风险 | 当前控制 | 剩余限制 |
| --- | --- | --- |
| 单来源伪造或分歧 | 固定高度，两个运营方一致，否则停止 | 共同上游/合谋未排除；严格策略降低可用性 |
| 错误部署 | chain ID、观察到的代码摘要、factory/WETH9、pool 身份 | 代码摘要不等同于官方源码等价审计 |
| 交易篡改 | 目标和 value 限制、接收地址绑定、独立 calldata 解码、SDK 最低值重算 | 同源恶意代码仍能改变 UI；发行来源必须可信 |
| 账户/网络/入口变化 | 监听后废弃计划，发送前再次核对；30 秒预览期限 | 钱包弹窗中的最终核对仍由用户完成 |
| 重复发送 | 同步 ref 锁、发送前持久化公开意图、同源 Web Locks、最终确认后解除 | 不同源/设备与清除站点数据不协调；不自动追踪替换哈希 |
| 成功误报 | 核对实际交易输入、池 Collect 与两代币实际 Transfer | 非标准代币和 fee-on-transfer 不在批准范围 |
| 重组与待确认 | 重查区块哈希，撤销旧结果，safe/finalized 分开 | 尚缺真实链重组下的浏览器验收 |
| 恶意恢复卡 | 字段白名单、uint256 范围、大小和数量限制 | 恢复卡是线索，不是可信发行证明 |
| 本地服务攻击 | loopback、Host 校验、无代理、拒绝穿越和 symlink | 设备本身被控制时无法保护用户 |
| 混合发行 | 清单和逐文件摘要、拒绝额外文件、重建恢复目录 | 必须从独立可信渠道保存清单摘要 |

固定区块读取还会检查区块号和时间戳的十六进制 quantity 格式、uint256 长度与 32 字节区块哈希；数值高度请求的返回高度必须完全相同。两个来源一致返回其他高度也不能通过。`safe`/`finalized` 标签允许返回实际数值高度，但仍检查字段结构；收据及恢复路径的后续数值区块核对不能被替换为其他高度。

新快照以两个来源较低头部往前两个区块固定，头部相差超过 300 块时停止。区块时间落后本机超过 300 秒或超前超过 30 秒时停止，避免超前时间影响退出 deadline。历史区块读取不套用新快照的时间窗口。本机时钟仍是依赖；这些检查不能证明两运营方的共同上游独立，也不验证完整共识或头部祖先链。

## 入口与发送门槛

生产发送只接受未被 Service Worker 控制的 loopback 本地模式，或文件验证成功的 TapeOut 客户端模式。远程静态站点、服务器模式和未验证客户端均只读。客户端状态中的链、名字、容器须有效，首页响应成功，文件验证标记及名字/容器/激活状态须与状态响应一致；请求有超时，读取期间控制器变化会撤回验证。

发送预检后重新查询入口，比较模式、名字和容器；区块正常推进不被当成身份变化。控制器切换立即清空计划并撤回旧入口状态，迟到的入口响应不得覆盖新状态。异步钱包检查返回后、写入待处理标记及发起发送请求之前，再同步检查操作代次与控制器引用，避免用检查期间失效的计划发起钱包请求。

这些检查只能约束当前受信代码观察到的状态；响应头来自控制器，不是独立发行认证。恶意 Service Worker、同源脚本、容器修改、网关启动链及已打开的钱包弹窗仍保留相应信任，不能据此宣称真实 TapeOut/钱包集成已验收。

## 待处理提交恢复

发送前保存公开账户、chain ID、仓位编号、调用摘要、时间和随机标识；不保存 calldata、签名或私钥。钱包返回后补充哈希。标记写入/回读失败时不调用钱包发送；若发送后补写哈希失败，原未知标记继续阻止新发送。只有明确的钱包拒绝码 4001 才清理未发送标记，其他中断保持未知。

Web Locks 使用同源排他锁；不支持该 API 时拒绝正式发送。普通操作历史与待处理记录分开，清空历史不解锁。已知哈希的恢复必须匹配实际发送者、原管理器、零 value 和调用摘要，复用历史领取核对，并检查最终区块与收据 canonical 哈希后清理。仅 included/safe、缺少 finalized 支持、重组或来源分歧均不解锁。

未知提交支持手动补入钱包中的交易哈希。候选值仅在内存保存并绑定当前待处理标识；完整哈希格式验证后才能查询。仅实际交易身份和调用摘要匹配后才保存哈希，后续仍须通过收据及最终性核对才能清除标记。补入无关交易、非零 value 或其他收款调用不提供解锁途径；未找到交易时也不替换未知标记。

恢复完成会同步历史，清除旧仓位、预览和发送上下文，避免把旧资产信息套在恢复交易上。会话中的收据高度下限独立于当前结果展示，即使读取失败或结果被清除，也不会允许下一次读取、预演或发送前重查使用更早快照。该下限不跨页面重载持久化，也不证明区块最终性。

首次收据与后续最终性核对分开处理：第二次核对失败/退回 pending 时撤回成功展示、标记待核对并恢复内存发送锁；第二次得到回滚或领取证据不足时展示最新结果，不保留第一次成功。

用户更换仓位、钱包或入口后，迟到的最终性响应也必须通过当前操作代次检查，不能重新覆盖新工作区。此保证已有模拟 provider 的生产 UI DOM 回归测试；测试内批准开关是夹具设置，生产配置仍关闭签名，不代表真实钱包已验收。

这会牺牲部分可用性：没有哈希的未知请求、掉单或替换/取消交易没有自动解锁；需另行检查钱包和链上状态。清除浏览器站点数据会移除本地保护；不同 origin/设备、恶意同源代码和用户在钱包独立发送仍无法协调。测试使用 DOM 存储及互斥 API 测试替身，不证明真实浏览器跨标签页和钱包验收完成。

## 依赖告警

本次 `npm audit --omit=dev` 返回 22 项：9 high、2 moderate、11 low。包括官方 SDK 依赖链上的 ethers/elliptic，以及合约包拉入的 Hardhat、watcher、undici、压缩与序列化工具。它们属于安装图；不能据此认定全部进入浏览器，也不能由打包体积小反推没有漏洞。

本产品通过注入钱包发送交易，不使用 ethers/elliptic 持有私钥或本地签名。本地服务器使用 Node 标准库，不使用上述 HTTP 工具。不过安装/构建过程与供应链仍有风险；完整可达性审阅尚未完成。未使用 `audit fix --force` 将官方 SDK 降级或盲目覆盖不兼容依赖。主网签名继续关闭。

`report:dependency-scope` 将扫描结果按安装路径对应到生产模块图，验证 lockfile、审计摘要、实际 chunk 与发行清单，失败时删除旧报告。它只输出 `present` / `not-observed` 与 `exploitability: not-assessed`；模块图可能包含被 tree-shaking 删除的内容，未出现的包仍可能影响安装或构建。不能据此关闭告警。详见 `DEPENDENCY-REVIEW.md`。

`verify:reproducibility` 从干净提交创建临时副本，固定依赖安装后连续构建两次，并与当前发行逐文件比较；失败不保留旧成功报告。这属于同机/同工具链的可重复性，不证明另一设备复现或依赖供应链安全。

## 发行前必须补齐

X Layer 固定分叉已通过一个实际部署仓位的组合退出、余额增量和剩余流动性核对。仍须完成批准资产的非标准行为检查、真实 TapeOut origin 的钱包与 SW 验收、网关故障与外部 API 阻断实验、独立代码审阅。付费容器发布和资产操作需要具体钱包、容器和预算。上述工作没有完成前不能向评委或用户宣称主网就绪。
