# TapeExit 实施任务与验收清单

日期：2026 年 10 月 27 日。配套主文件：`TapeExit-Development-Plan.md`。

状态约定：全部任务目前均为“未开始”；研究中读过资料不算实现完成。本文是可导入项目管理工具的任务底稿，不表示已创建外部任务或派工。

## 1. 估算与关键路径

按人日估算，不把并行工时误写成自然日。技术未知、主网发布与独立审阅可能增加成本。

| 工作包 | 初估人日 | 主要负责人 |
| --- | --- | --- |
| A：技术核实与基础 | 4–6 | 工程 A/B |
| B：读取、数学与交易 | 7–10 | 工程 A |
| C：钱包与产品界面 | 6–9 | 工程 B |
| D：TapeOut、入口与恢复包 | 7–10 | 工程 B |
| E：测试、安全与演练 | 6–9 | 工程 A/B + 审阅 |
| F：用户验证与商业证据 | 5–8 | 产品支持 |
| G：发行与参赛 | 4–8 | 全队 |
| 总计 | 39–60 | 不含 20% 缓冲 |

带缓冲总量约 47–72 人日。两人六周的常规工作容量约 60 人日，不能承诺上限全部完成。首周实测后重新估算；P1 只在剩余容量明确时接入。

关键路径：

```text
A01 部署核实 → A02 真实来源钱包 → A03 完整退出试验
  → B01/B02 快照与计算 → B03/B04 交易与模拟
  → C03 签名状态机 → D03 实际发布
  → E03/E04 故障与独立审阅 → G02 发行 → G04 提交
```

预算批准、付费部署、实际主网操作、外部沟通是各自独立事项；本清单不等于这些动作已经执行。

## 2. A：技术核实与基础

### A01 官方部署身份核实

- 优先级：P0。依赖：无。
- 操作：两个运营方读取链 ID、管理器代码、工厂与池身份；保存区块号和哈希。
- 交付：`deployment-verification.json`、来源说明、支持配置。
- 验收：不能仅凭代码非空；错误链、错误工厂、错误池都被拒绝。
- 阻断：身份核实失败时不能进入主网适配开发。

### A02 TapeOut 真实来源与钱包试验

- 优先级：P0。依赖：基线 TapeKit。
- 操作：真实 origin 下测试 SW 接管、EIP-6963 provider、读取账户与链。
- 交付：浏览器 trace、来源状态、兼容钱包清单。
- 验收：至少 Chrome 桌面的一款目标钱包成功；iframe、server 模式和客户端模式分别标记。
- 阻断：未通过不得用普通 Web2 页面代替 TapeOut 路径宣称集成完成。

### A03 完整退出技术试验

- 优先级：P0。依赖：A01。
- 操作：建立可控官方协议夹具；在固定 X Layer 分叉核实实际部署。
- 交付：减少流动性与领取组合调用、执行收据、余额/仓位断言。
- 验收：用户直接调用管理器，无新增授权；collect 失败时整体回滚。
- 注意：分叉里的测试权限不得延伸到主网。

### A04 仓库、工具链与 CI

- 优先级：P0。依赖：无。
- 交付：运行时版本、lockfile、类型检查、基础测试、构建、许可证清单。
- 验收：干净机器可依说明安装并启动；生产构建不含测试私钥与 mock。
- 规则：先完成小模块，出现真实共享需求再拆 packages。

### A05 依赖和成本基线

- 优先级：P0。依赖：A02、A04。
- 交付：网络依赖图、bundle 字节、链上发布估算与 activation 待核字段。
- 验收：记录原始文件大小；无远程脚本；未知费用不填零。

## 3. B：读取、数学与交易

### B01 固定区块严格读取

- 优先级：P0。依赖：A01、A04。
- 交付：RPC 运营方配置、严格读取模块、错误类型。
- 验收：两域名同运营方不够；两运营方一致通过；有效冲突阻断；超时与冲突区分。
- 测试：同高度不同哈希、错误 chain ID、429、批处理降级和旧区块。

### B02 仓位快照与 SDK 计算

- 优先级：P0。依赖：B01、A03。
- 交付：精确整数模型、池身份核对、退出比例与最低输出。
- 验收：6/8/18 decimals、uint256 token ID、单边仓位、极小额与 100% 全量。
- 不允许：浮点金额、硬编码代币 symbol、手写近似 V3 数学。

### B03 交易构建与解码检查

- 优先级：P0。依赖：B02。
- 交付：`ExitPlan`、明确字段编码 hash、独立解码校验。
- 验收：只允许指定管理器的 decrease/collect 路径；recipient 与账户绑定；value 为零。
- 测试：篡改 manager、recipient、token ID、方法顺序与插入未知调用均失败。

### B04 预演与 gas

- 优先级：P0。依赖：B03。
- 交付：相同 sender、区块和 calldata 的双运营方 eth_call，gas 估算。
- 验收：解码组合返回；任何关键冲突或 revert 阻断；费用缺失不显示零费用。
- 注意：两个运营方 gas 估算不必数值相等。

### B05 收据与领取核对

- 优先级：P0。依赖：B03、B01。
- 交付：tx input 核对、收据状态、事件解析、剩余仓位检查。
- 验收：不只看管理器 Collect 事件；区分池实际转出、标准代币 Transfer、余额辅助值。
- 测试：无关 Transfer、NFT Transfer、舍入差异、同区块其他交易。

### B06 仅领取与边界路径

- 优先级：P0。依赖：B02–B05。
- 交付：collect-only 状态、空操作阻断、非标准代币只读。
- 验收：无 liquidity 时不执行 decrease；collect 不虚构合约 deadline；不自动 burn NFT 或 unwrap。

## 4. C：钱包与产品界面

### C01 钱包发现与选择

- 优先级：P0。依赖：A02、A04。
- 交付：注入 provider 选择、连接、断开和切链。
- 验收：多个扩展不抢选；元数据不作为 HTML；不发个人签名请求。
- 测试：4001/4100/4200/4900/4901 等 provider 错误各有明确映射。

### C02 仓位与预览工作区

- 优先级：P0。依赖：B02、C01。
- 交付：第一屏直接可用的 token ID 输入、只读查询、退出比例、预估与最低值。
- 验收：地址可核对；非 owner 不给签名；零值和未知值区分。
- 视口：360、390、768、1280、1440 px。

### C03 签名前复核与状态机

- 优先级：P0。依赖：B03、B04、C01。
- 交付：不可变交易核对页、账户链监听、过期处理、发送状态机。
- 验收：账户/链改变立即废弃计划；发送结果未知时禁止自动重试。
- 测试：双击、用户取消、断线、pending、replacement、revert、reorg。

### C04 结果页与本地历史

- 优先级：P0。依赖：B05、C03。
- 交付：执行/领取/最终确认分离展示，公开字段证据导出。
- 验收：刷新后重新检查；历史不保存可直接发送的旧计划；支持删除。

### C05 入口状态、语言和无障碍

- 优先级：P0。依赖：C02、D01。
- 交付：运行模式、发行 ID、依赖详情、中英文关键文案。
- 验收：键盘、焦点、读屏、错误关联可用；server 模式仅只读。

## 5. D：TapeOut、入口与恢复包

### D01 固定 TapeKit 集成

- 优先级：P0。依赖：A02。
- 交付：固定提交、变更说明、最小网关策略差异。
- 验收：保留上游保留路径，实际测试三段多链主机名；不以旧 README 覆盖源码行为。

### D02 构建清单和版本核对

- 优先级：P0。依赖：A04、C02。
- 交付：静态发行文件、manifest、来源清单与资源 hash。
- 验收：文件名含摘要；未声明资源和混合版本被识别；清单 hash 不发生自引用。

### D03 X Layer 实际发布

- 优先级：P0。依赖：D01、D02、预算与发布操作确认。
- 交付：真实电路、容器、站点身份、激活状态、逐文件回读结果。
- 验收：与本地构建逐字节核对；未激活、失配或分块缺失不能作为正式可用发行。

### D04 主网关与备用网关

- 优先级：P0。依赖：D03。
- 交付：两个可核对入口与共用基础设施说明。
- 验收：主域名不可用时备用入口可用；不把同云双域名包装成完全独立。

### D05 本地恢复包

- 优先级：P0。依赖：D02、C03。
- 交付：静态应用、无运行时 npm 依赖的 loopback server、manifest、恢复说明。
- 验收：干净机器验证文件后启动，保持注入钱包来源，使用 RPC 完成同一任务。
- 安全：Host 校验、无公网绑定、无代理、无任意文件读取、无路径穿越。

### D06 恢复卡与导入

- 优先级：P0 为 JSON 导出与导入；二维码和图形排版为 P1。
- 依赖：D02、D03、C04。
- 验收：只导入身份与位置线索；不能覆盖 manager、recipient 或注入 calldata。

### D07 有限分页发现

- 优先级：P1。依赖：B02。
- 交付：经部署验证后的 ERC-721 枚举、分页和取消。
- 验收：无第三方索引器时可用；失败不影响已知 token ID。

## 6. E：测试、安全与演练

### E01 金额和不变量测试

- 优先级：P0。依赖：B02、B03。
- 交付：边界与性质测试。
- 验收：任意生成的有效计划都满足账户、目标、接收人、权限与整数边界。
- 不以组件快照替代资金路径测试。

### E02 官方协议和分叉回归

- 优先级：P0。依赖：A03、B06。
- 交付：固定编译器和官方协议版本的本地 fixture，指定区块的分叉说明。
- 验收：正常退出、collect-only、slippage revert、atomic rollback、权限失败全部覆盖。

### E03 三种独立性演练

- 优先级：P0。依赖：D03–D05、C03。
- 交付：断业务后台、断主网关、断网页托管三组 trace。
- 验收：故障真正生效，版本一致，交易或分叉结果可核对。
- 不允许：关闭 SW 以便测试后仍宣称覆盖正式运行路径。

### E04 安全审阅

- 优先级：P0。依赖：交易路径稳定。
- 交付：审阅人、范围、版本、发现、修复与复测。
- 验收：资金风险无未解决问题；未覆盖部分明确。
- 不能把内部 review 或依赖扫描宣传为独立安全审计。

### E05 真钱包和恢复包验收

- 优先级：P0。依赖：C03、D05。
- 交付：Chrome + OKX Wallet 的目标矩阵；第二款钱包作为兼容性增强。
- 验收：账户切换、链切换、取消、实际签名内容、localhost 注入和重启均已人工核对。

### E06 小额主网验证

- 优先级：P0 交付目标，执行需具体交易与费用确认。
- 依赖：E01–E05、支持代币、实际钱包与资产。
- 交付：实际链上证据、费用、剩余仓位与领取核对。
- 如未完成：保留为未通过，不用分叉结果替代。

## 7. F：用户与商业验证

### F01 用户任务研究

- 优先级：P0。依赖：目标画像明确。
- 交付：经许可的访谈记录、真实故障案例和现有替代方式。

### F02 可用性测试

- 优先级：P0。依赖：C04、演示环境。
- 交付：至少 5 位目标用户的任务完成、时间、错误和协助记录。
- 验收：不在第一次测试前逐步教完再统计为独立成功。

### F03 替代方案对照

- 优先级：P0。依赖：E03。
- 交付：IPFS、开源本地前端、浏览器调用、TapeExit 同任务比较。
- 验收：公布同一故障范围和网络白名单，不以不公平环境制造优势。

### F04 协议方试点与价格假设

- 优先级：P0。依赖：D05、F01。
- 交付：集成说明、成本模型、维护边界、真实试点或意向。

## 10. 每周交付检查

每周结束仅回答五件事：

1. 哪条完整用户任务已经可以实际运行？
2. 哪项独立性和安全边界已经有可复现证据？
3. 哪些只是界面或假设，不能宣传为完成？
4. 下周哪项阻断最可能影响交付？
5. 剩余人日是否要求裁掉 P1？

任务完成必须关联代码版本、测试或实际记录。不能用“已写文档”“已设计界面”替代交易或入口验收。
