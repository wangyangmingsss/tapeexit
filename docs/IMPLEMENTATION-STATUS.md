# TapeExit 实施状态

本表区分代码、自动化测试与外部验收。生成于 2026-10-27，不能将“已实现”理解为已通过全部原计划验收。

## 已实现且可本地复现

- X Layer 主网只读部署核对；管理器、工厂代码摘要固定。
- 两运营方严格读取、固定区块和重组检查。
- 区块号/时间戳 quantity、uint256 长度与 32 字节哈希检查；返回高度必须等于请求高度。新快照拒绝超过 300 秒的旧时间或超前 30 秒的时间，历史验证不套用新快照时间窗口。
- V3 仓位直接所有权、工厂/池/资产身份读取。
- 官方 SDK 精确整数计算；部分/全部退出、单边仓位和仅领取。
- 原管理器组合调用、收款地址绑定、value 为零、独立解码和最低输出重算。
- 发送前账户/链/预览检查、重复发送锁、提交未知时停止。
- 实际交易输入、池 Collect 和 ERC20 转出事件交叉核对。
- pending、revert、重组后的成功撤销、safe/finalized 分离。
- 已知 nonce 消耗时停止并提示检查替换交易；不自动寻找替换哈希。
- 中英文工作区、复核弹窗、焦点管理、本地历史与证据导出。
- 交易哈希即时持久化，刷新后按真实交易重建历史领取证据；失败撤回旧成功状态，清空中的异步复核不复活记录。
- 发送前持久化待处理意图、Web Locks 同源互斥、刷新恢复和独立历史清空；已知哈希核对实际调用及最终性后解除，未知/损坏记录保持阻止发送。真实跨标签页与钱包验收仍待完成。
- 恢复完成同步真实结果并清除旧仓位/预览；会话收据高度下限覆盖读取、预演和发送前重查。首次成功后的最终性复核失败会立即撤回成功状态并恢复发送锁。
- 钱包响应丢失后可补入交易哈希；仅匹配原始提交且最终确认才能解锁。格式错误不查询，错误发送者/目标/value/调用不写入，候选输入绑定当前待处理标识。
- 生产入口只接受本地模式或验证成功的 TapeOut 客户端；核对状态与首页身份，预检后重读入口。控制器切换撤回入口/计划，异步钱包检查后再次检查操作代次及控制器；相关测试为协议响应和 DOM 夹具，真实钱包与 SW 验收仍待完成。
- 严格恢复卡导入与可单独运行的本地恢复包。
- 带摘要的发行清单、拒绝混合/额外资源、生产演示分离。
- 固定 TapeKit 源码获取及校验、专用网关构建和保留路径服务器。
- 按文件摘要和分块索引构建的未签名发布计划。
- 发布清单要求干净源提交；额外/缺失文件、符号链接、重复/保留路径和摘要不符均停止；入口与 fallback 最后编码。
- 发布后只读回读工具：独立清单摘要、两来源固定区块、完整路径/fallback、文件元数据及分段字节比对；仅协议响应测试通过，实际容器验收未完成。
- 发布文件路径与 fallback 修正为无前导 `/`，并用固定 TapeKit 实际路径解析函数验证；此前候选版的兼容步骤已在远程通过。

## 当前明确限制

生产 `RELEASE_APPROVED=false`，`SUPPORTED_TOKENS=[]`。不存在经过批准的主网发送路径。不要通过随意改开关绕过发布门槛。

模拟演示只有测试资产和预设结果。真实原站隔离必须通过网络阻断和请求记录证明，不能用页面状态开关代替。

本机 Chromium 仍在 macOS 沙箱 MachPortRendezvous 初始化阶段被拒绝；此前 16 项已在 GitHub Ubuntu 运行并取得截图。新增用例须检查当前提交的 CI；真实钱包和真实容器不由 DOM/夹具通过结果替代。

公开仓库 `wangyangmingsss/tapeexit` 已创建并上传此前全部提交；每次继续开发后核对远程提交及对应 CI，不复用旧通过结论。

## 发布顺序

先完成真实浏览器与目标钱包验收、支持资产审阅。随后审阅发布预算、准备真实 TapeOut 容器，逐文件发布回读，部署备用网关，完成原站失联与本地恢复演练。所有外部证据齐全后才能启用生产签名和录制正式参赛演示。
