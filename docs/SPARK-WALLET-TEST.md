# Spark USDC 真实钱包小额测试

本工具服务于明确的单钱包主网实测。它和公开应用分开运行，不改变生产签名开关，不代表独立安全审阅。

## 固定范围

- X Layer，Chain ID 196。
- 原钱包：`0x101FD328a0B2Fd9E853909651dAB1c0B55947C03`。
- 金库和 USDC 身份沿用 [Spark 金库适配](SPARK-USDC-VAULT.md) 的固定配置。
- 开始时要求原钱包没有 spUSDC，避免将既有份额混入测试。
- 存入恰好 1 USDC。余额或存款额度不足时，不先请求授权。
- 没有足够授权时，仅将本次金库的 USDC allowance 设置为 1 USDC，禁止无限授权。
- 赎回存入后份额的一半，再赎回剩余份额，收款人和份额持有人固定为原钱包。
- 每笔 Gas 上限 1,000,000；Gas 单价上限 30,000,000 wei；最多 12 次包含取消与重试的预约。
- 总 EVM Gas 预约预算上限 0.00036 OKB，每笔还需单独确认实际预览费用。链特有附加费以钱包显示为准。

无现有授权时通常为 4 笔钱包交易：批准、存入、部分赎回、赎回剩余份额。有足够现有授权时为 3 笔。恢复查询不请求签名。

## 执行

从干净、已提交的源码运行：

```sh
npm run test:vault-wallet -- /ABSOLUTE/PATH/wallet-journal.json 4196
```

在安装 OKX 扩展的 Chrome 打开 `http://127.0.0.1:4196/`。

1. 连接指定原钱包，选择 X Layer。
2. 点击“准备：批准本次 1 USDC”，查看模拟、金额、费用和 90 秒有效期。已有授权记录时，按钮直接显示当前阶段。
3. 勾选该笔确认，再点击“在 OKX 钱包中确认：当前操作”，在扩展内确认。勾选复选框本身不会请求钱包交易。
4. 只读核验通过后，页面清除上笔预览与勾选，3 秒后自动准备下一步预览。授权成功后下一步为“存入 1 USDC”；每笔仍需重新勾选并点击钱包确认。可取消自动衔接，改为手动准备。
5. 最后导出金库恢复文件，在新版只读应用“USDC 金库”导入并重新核验。
6. 使用相同 journal 重启工具，点击“重新核验全部记录”，检查恢复结果。刷新页面后保留已完成阶段，不重复授权。

## 保留未知结果

服务在返回钱包交易前持久化并 fsync 预约。没有哈希、RPC 不可用、未最终确认、金额不一致或余额变化不匹配，都保留待处理状态，禁止再发同笔。

钱包请求超过 90 秒不代表取消。若晚到的哈希返回，页面仍尝试保存；也可从钱包历史复制完整哈希。只有在钱包中明确取消或拒绝、无哈希且 latest/pending nonce 未变时，才可按“记录取消”释放预约。不要删除 journal 或锁文件以重发。

所有服务仅绑定 loopback，拒绝外部 Host/Origin、非同源 JSON、未知字段与超限请求。服务没有私钥、签名或广播接口。

## 核验与限制

预览重新核对金库及 USDC 实现身份、代理指针、USDC 暂停/黑名单与钱包代码。每次续步重新检查历史交易，不能直接相信 journal 的“已确认”标签。

确认核对实际调用、链、账户、收据、nonce、已花费 Gas、最终确认、批准/存款/转账事件，以及父区块和收据区块的余额与份额。赎回复用公开应用的 `inspectVaultRecovery`。

钱包扩大未使用的 Gas envelope 不单独导致失败，但实际使用量及结算单价不能超过本笔同意的上限。

`deposit` 和 `redeem` 没有本工具可设置的链上最低到账字段。预览与核验参考下限并非最低到账保证。USDC 和金库仍有发行方、暂停、冻结、升级与流动性风险；区块末余额核对也无法隔离同一区块其他活动。

```sh
npx vitest run tests/vault-wallet.test.ts
npm run verify:vault-wallet-fork
```

第二条在真实部署的隔离分叉上运行同一个钱包协调器，检查批准、存入、部分/全部赎回、重启、恢复文件导入和篡改交易拒绝。测试仅在分叉中模拟原账户执行，不是主网或 OKX 扩展的验收证据。
