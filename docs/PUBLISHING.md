# TapeExit 发布手册

## 构建和封存

从干净提交执行 `npm ci`、类型检查、测试和生产构建。运行 `check:release`，保留 manifest、清单摘要、源提交及 `sourceDirty` 状态。演示与生产包放在不同目录，不将演示包上传到正式站点。

固定 TapeKit 提交和压缩包摘要；构建专用网关时保留 `/sw.js` 与 `/.tape/`。当前 CSP 限制的是站点响应，上游内核自身的链读取、启动文件信任及网关配置仍需审阅。

## 链上准备

准备 X Layer 上真实电路 NFT、处理器编号和容器地址。独立核对持有人、开通状态、挂单/锁定状态、SiteRegistry 与 DomainBinding 的当前实现槽和允许版本。不能把其他链的价格、地址或处理器编号套用到 X Layer。

读取 `monthlyFee()` 和 `isContainerLive(container)`。所有费用以 OKB 的链上值为准，不能承诺免费 gas。应用上传、activation 和域名分别估算，给出有上限的预算后再执行付费操作。

## 未签名发布计划

`npm run plan:publish -- <容器地址>` 生成按顺序排列的原始调用数据。脚本不检查容器所有权，不提供发送功能，也不构成完整部署器。

生成前要求清单包含有效源提交且 `sourceDirty=false`，检查 chain 196、关闭签名标记、文件大小、SHA-256、路径和 MIME。重复或保留路径、额外/缺失文件、符号链接会中止生成。这只核对本地发行输入；不会证明源提交已被审阅、容器可信或预算获批。

每个文件首先 `putFile`，携带完整文件 SHA-256 与第一段数据；后续 `appendChunk` 的 `expectIndex` 必须与当前分块数一致。中断后先读取实际状态，不盲目重放。计划将入口 `index.html` 与 fallback 放在最后，减少半成品可见窗口；仍须在逐文件回读后才允许切换入口。

## 上线验收

1. 每个文件从两个运营方回读，完整重组后与本地字节逐一核对。
2. 核对三段主机名 `<ID>-2-<processor>`、chain 196、容器和 activation 状态。
3. 在真实客户端模式读取 `/.tape/status?json=1` 和 `x-tape-mode`、`x-tape-verified` 等响应头。
4. 使用注入钱包测试账户请求、切链、拒绝、账户变化、SW 更新和提交未知。
5. 主网关不可用时测试独立备用网关；记录共同云服务、DNS、CDN 和 RPC 依赖。
6. 阻断原站和专属 API，记录实际网络请求和真实链上结果。演示开关或模拟结果不能作为此项证据。
7. 在干净环境校验本地恢复包，完成同一任务并保存公开证据。

## 托管和更新

生产网关需要可信 HTTPS、通配证书、保留路径的固定静态映射，以及其他路径到 bootstrap 的回退。对 `sw.js` 和启动脚本使用明确更新策略，避免旧 SW 与新站点混用。可复用构建出的 `dist-gateway/`，但本项目尚未配置实际生产域名或云账户。

容器内容可更新，发行摘要需要提前另存。升级前审查差异；发现链上代码/文件或 RPC 分歧时关闭签名。server 兼容模式仅只读，不展示为客户端独立验证。
